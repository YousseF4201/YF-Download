## المرحلة 1: محرك التحميل الأساسي (Core Download Engine)
> **الهدف:** تحميل ملف كامل عبر اتصال واحد والتحقق من سلامة البيانات.

### ما تم تنفيذه:
- [x] طبقة الشبكة: تنفيذ طلبات HTTP GET وتدفق البيانات مباشرة إلى القرص (.yfpart).
- [x] استعلام HEAD لمعرفة حجم الملف ودعم ترويسة Range واسم الملف من الترويسات.
- [x] تتبع التقدم اللحظي (حجم محمل، نسبة مئوية، سرعة متوسطة، وقت متوقع ETA).
- [x] التعامل مع الأخطاء وإعادة المحاولة التلقائية (Exponential Backoff).
- [x] التحقق من سلامة الملف النهائي عبر Checksum (SHA-256).
- [x] أداة السطر البرمجي yf-cli للتجربة المباشرة من الطرفية.

## المرحلة 2: التحميل المجزأ والاستئناف (Multi-Segment & Resume)
> **الهدف:** تسريع التحميل بتقسيم الملف + استئناف التحميل عند الانقطاع وتزامن الحالة.

### ما تم تنفيذه:
- [x] تقسيم الملف إلى أجزاء (segments) بالاعتماد على حجم الملف وعدد الاتصالات المتزامنة.
- [x] تحديد عدد الاتصالات المتزامنة (افتراضياً 8 أجزاء، مع إمكانية التخصيص).
- [x] التحميل المتوازي عبر ترويسة HTTP Range: bytes=start-end باستخدام tokio tasks.
- [x] كتابة تدفق بيانات كل جزء في ملفات مؤقتة منفصلة (.part.N).
- [x] تجميع الأجزاء في ملف نهائي واحد بدقة وحذف الأجزاء المؤقتة بأمان.
- [x] طبقة قاعدة البيانات المحلية SQLite (rusqlite bundled) لتخزين بيانات المهام والأجزاء.
- [x] آلية استئناف التحميلات غير المكتملة وحساب النطاق المتبقي بدقة لكل جزء.
- [x] معالجة الانقطاعات وإعادة المحاولة المستقلة لكل جزء والاستعادة الذاتية عند الإقلاع.
- [x] التراجع التلقائي للتحميل الفردي (Fallback) في حال عدم دعم الخادم للتجزئة أو رجوع كود 200.
- [x] دعم أدوات السطر البرمجي yf-cli لخيارات التحكم (--segments, --resume, --db, --list).
- [x] اختبارات تكامل وشاملة E2E تغطي التحميل المتوازي والاستئناف والتحقق من الـ Checksum.

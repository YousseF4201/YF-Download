# ADR-002: إطار واجهة المستخدم الرسومية

**الحالة:** مقترح — ينتظر الموافقة
**التاريخ:** نوفمبر 2026

## السياق

نحتاج لإطار واجهة مستخدم رسومية (GUI) يعمل على ويندوز ولينكس، يدعم RTL للعربية، وينتج تطبيقًا خفيفًا.

## الخيارات

### 1. Tauri + Svelte ✅ (الاختيار)
| الجانب | التقييم |
|--------|---------|
| حجم التطبيق | ممتاز — ~10-20 MB (يستخدم WebView الأصلي) |
| استهلاك الذاكرة | ممتاز — ~20-50 MB |
| التوافق مع Rust | أصلي — Tauri مكتوب بـ Rust |
| دعم RTL | ممتاز — CSS يدعم RTL بسهولة |
| تعدد الأنظمة | ويندوز ولينكس (وماك لو أردنا لاحقًا) |
| Svelte | خفيف وسريع، لا virtual DOM، حجم حزمة صغير |

### 2. Tauri + React
| الجانب | التقييم |
|--------|---------|
| كل ما سبق | مشابه |
| الفرق | React أشهر لكن أثقل قليلًا من Svelte، virtual DOM زائد عن الحاجة |

### 3. Electron + React
| الجانب | التقييم |
|--------|---------|
| حجم التطبيق | سيئ — ~150-200 MB (يحمل Chromium كاملًا) |
| استهلاك الذاكرة | سيئ — ~100-300 MB |
| التوافق مع Rust | ضعيف — يحتاج Node.js |
| السبب ضده | مدير تحميل يجب أن يكون خفيفًا، ليس تطبيق ويب ضخمًا |

### 4. Qt (مع ربط Rust)
| الجانب | التقييم |
|--------|---------|
| واجهة أصلية | نعم |
| التوافق مع Rust | ضعيف — الربط (bindings) غير ناضج |
| دعم RTL | موجود لكن أعقد من CSS |
| الرخصة | LGPL — يحتاج انتباهًا لتوافق الرخص |

## القرار

**Tauri + Svelte** — لأنه:
1. **خفيف جدًا** — مدير تحميل يجب أن يكون سريعًا وخفيفًا، ليس تطبيقًا ضخمًا.
2. **متكامل مع Rust** — النواة والإطار بنفس اللغة، لا حاجة لجسر معقد.
3. **Svelte أخف من React** — حزمة أصغر، أسرع في التشغيل، لا virtual DOM.
4. **CSS يدعم RTL بسهولة** — `direction: rtl` مع `dir="rtl"` يكفيان.
5. **يستخدم WebView الأصلي** — WebView2 على ويندوز، WebKitGTK على لينكس.

## العواقب

- Svelte أقل شهرة من React — مساهمون أقل قد يعرفونه.
- على لينكس يعتمد على WebKitGTK — يحتاج تثبيته كتبعية نظام.
- Tauri 2.x أحدث — بعض الوثائق قد تكون لنسخة 1.x.
